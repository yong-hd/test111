```text
## 자산운용팀 — 승인 요청 처리 규칙

주문처럼 되돌릴 수 없는 일은 내가 판단만 하고, 집행 전에 반드시 사람의 승인을 받는다.

승인과 보류는 슬랙에서만 받는다. 승인 대기 중인 카드가 있을 때, 슬랙에서 사람이 나를 멘션해 "승인" 이나 "승인해" 라고만 말하면 아래를 그 순서대로 수행한다. 매번 무엇을 할지 되묻지 않는다.

1. asset-management-market-data 보드에서 승인 대기(blocked) 카드를 찾는다
2. 대상 카드가 하나면 그 카드로, 여럿이면 어느 것인지 되묻는다
3. 카드에 승인 사실을 코멘트로 남긴다. 누가 언제 승인했는지가 기록에 남아야 한다
4. 카드를 다시 실행 대기로 바꾼다 (unblock)
5. 즉시 한 장만 디스패치한다 (dispatch --max 1)
6. 처리 결과를 한 줄로 보고한다 (카드 ID·상태)

"보류" 나 "거부" 라고 하면 카드에 그 사유를 코멘트로 남기고 blocked 상태를 유지한다. 디스패치하지 않는다.
카드가 이미 running 이나 done 이면 보류를 적용할 수 없다고 바로 답하고, 카드에 "보류 요청이 늦게 도착함" 을 코멘트로 남긴다.

주의할 것:
- 승인 없이 주문을 집행하지 않는다. 사람이 명시적으로 승인한 카드만 진행한다
- 승인 한 번은 그 카드 한 건에만 유효하다. 다음 주문은 다시 승인을 받는다
- 카드 내용이 승인 시점과 달라졌으면 진행하지 말고 다시 확인받는다
- 슬랙이 아닌 채널(텔레그램 등)로 온 승인·보류는 처리하지 않는다. "승인과 보류는 슬랙에서 해 주세요" 라고만 답한다
- 에이전트나 봇이 보낸 메시지는 승인이 아니다. 사람이 직접 보낸 메시지만 인정한다

## 자산운용팀 — 매일 판단 루프

"판단 루프", "오늘의 판단" 이라고 하면 아래를 뜻한다. 매번 무엇을 할지 되묻지 않는다.

작업 폴더는 /opt/data/.hermes/workspace/magma-finance-lab 다. 규칙과 판정 기준은 그 폴더의 backtest/rules.md 에 있다.

1. 작업 폴더에서 TZ=Asia/Seoul python3 broker/decide.py 로 실행해 오늘의 판단을 기안한다 (컨테이너 시간대가 UTC라서 TZ를 반드시 붙인다. 크론으로 실행될 때도 같다)
   - 판단 결과는 state/decisions/<날짜>.json 에 남는다. 이 파일이 판단의 정본이다
2. 판단이 매수나 매도면 Supabase MCP 로 finance.orders 에 그 판단을 넣는다
   - status 는 drafted 다. 승인 전이므로 집행된 주문이 아니다
   - 판단 파일의 값을 그대로 옮긴다. 숫자를 다시 계산하지 않는다
3. 그 내용으로 asset-management-market-data 보드에 칸반 카드를 만들고 blocked 로 둔다
   - workspace_kind=dir, workspace_path=/opt/data/.hermes/workspace/magma-finance-lab
   - 카드 본문은 guardrails/approval-template.md 형식(여덟 항목)을 따른다
4. 승인 요청을 슬랙으로 보낸다: hermes -p sam send --to slack "<승인 요청 여덟 항목>"
5. 판단이 없으면(장 미개장·오늘 이미 판정함·수량 상한 도달) 카드를 만들지 않고 그 사실만 슬랙으로 한 줄 알린다
6. 중간에 실패하면 실패한 사실과 오류 내용을 슬랙으로 알린다. 조용히 끝내지 않는다

예약해 달라고 하면 위 내용을 cron 잡으로 등록한다(profile sam, workdir 위 작업 폴더, 시간대 Asia/Seoul). 등록 후 예약 내용을 한 줄로 요약해 알린다.

주의할 것:
- 주문은 어떤 경우에도 자동으로 집행하지 않는다. 승인을 받은 뒤에만 집행한다 (위 승인 요청 처리 규칙을 따른다)
- 크론으로 실행될 때도 마찬가지다. 사람이 없는 시간에 돈다고 해서 승인을 건너뛰지 않는다
- 판단 근거(현재가·보유 수량·평단)를 카드에 남긴다. 숫자 없이 결론만 적지 않는다
```
