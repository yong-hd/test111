# 8.1 보완 — 키움 CLI를 Hermes 컨테이너 안에 설치하기

2026-09-28 점검 결과, 컨테이너 안에서 `command -v kiwoomcli`가 **비어 있었습니다.**
8.2부터는 Sam이 컨테이너 안에서 `kiwoomcli`를 호출하므로(수집 카드, 18:30 크론, 8.4 집행),
키움 CLI와 자격 증명은 **컨테이너 안, `/opt/data` 볼륨 위에** 있어야 합니다.
App Key를 발급받은 것만으로는 아직 부족하고, 이 문서의 설치와 연결을 끝내야 합니다.

> 호스트(`srv1840967`)에 `kiwoomcli setup`을 이미 했다면, 그건 컨테이너가 볼 수 없습니다. 컨테이너 안에서 다시 합니다.

---

## 왜 강의 방법 그대로는 안 되나

`kwcli`는 파이썬 `keyring` 라이브러리로 App Key·Secret을 저장합니다.
macOS는 Keychain, 데스크톱 리눅스는 GNOME Keyring이 그 뒤를 받쳐 주지만,
이 컨테이너(root, 화면 없음, DBus 없음)에는 **받쳐 줄 저장소가 없습니다.** 그래서 `kiwoomcli setup`이
"지원되는 keyring 백엔드를 설치해 주세요"로 멈춥니다.

선택지:

| 방법 | 재시작 후 | 크론·게이트웨이에서 | 판단 |
| --- | --- | --- | --- |
| A. `keyrings.alt` 파일 백엔드 | 그대로 동작 (`/opt/data`에 저장) | 동작 (설정 파일이 HOME 기준이라 모든 프로세스가 공유) | **권장 (모의계좌 한정)** |
| B. `gnome-keyring` + DBus | apt 패키지가 재생성 시 사라짐, 매번 unlock 필요 | 게이트웨이를 같은 DBus 세션에서 띄워야 함 | 무인 운영에 부적합 |
| C. 환경변수(`.env`) | — | — | 강의 규칙상 금지 |

A는 키를 **root만 읽을 수 있는 파일**(`/opt/data/.local/share/python_keyring/`)에 둡니다.
OS 수준 암호화는 없으므로 **모의계좌(demo) 전용**으로만 쓰고, 실계좌 키는 절대 넣지 않습니다.
강의 `broker/README.md`의 "실계좌라면 별도 OS 사용자·컨테이너·실행 정책이 필요"와 같은 선입니다.

## 설치 (컨테이너 안, 한 번)

```bash
# 호스트 (root@srv1840967)
export HC=$(docker ps --format '{{.Names}}' | grep hermes-agent | head -1)
docker exec -it -u hermes "$HC" bash -l
```

컨테이너 안에서 (처음부터 `-u hermes`로 들어가면 7)의 소유권 변경이 필요 없습니다):

```bash
# 1) kwcli + 파일 keyring 백엔드 (kwcli는 Python 3.13+ — uv가 알아서 받아 /opt/data에 둠)
uv tool install kwcli --with keyrings.alt
command -v kiwoomcli            # /opt/data/.local/bin/kiwoomcli 이면 정상

# 2) keyring이 파일 백엔드를 쓰도록 설정 (HOME=/opt/data 기준, 모든 프로세스 공통)
mkdir -p ~/.config/python_keyring
cat > ~/.config/python_keyring/keyringrc.cfg <<'CFG'
[backend]
default-keyring=keyrings.alt.file.PlaintextKeyring
CFG

# 3) 백엔드 확인 — PlaintextKeyring 이 보이면 정상
~/.local/share/uv/tools/kwcli/bin/python -c 'import keyring; print(keyring.get_keyring())'

# 4) 강의 8.1의 setup (서버 demo, 별칭 모의계좌, 가려진 입력창에만 키 붙여넣기)
kiwoomcli setup

# 5) 권한 잠그기 (파일은 600, 폴더는 700)
chmod 700 ~/.local/share/python_keyring
chmod 600 ~/.local/share/python_keyring/*

# 6) 확인
kiwoomcli auth status --profile 모의계좌
kiwoomcli doctor
```

`auth status` 통과 기준은 강의 8.1 표와 같습니다. `모드: demo`, `자격 증명 존재: 예`, `토큰 유효: 예`,
`지금 API 호출 가능: 예`. `자격 증명 출처`는 keyring으로 표시되며, 이 환경에서는 실제로 위의 파일 백엔드입니다.

uv 도구 경로가 다르면 3)은 `uv tool dir`로 위치를 확인해 바꿉니다.

### 7) 게이트웨이 사용자에게 소유권 넘기기 (이 VPS에서 필수)

이 이미지의 게이트웨이는 root가 아니라 **`hermes` 사용자**(uid 10000, HOME `/opt/data`)로 돕니다
(`ps -o user,pid,cmd -p <hermes gateway status의 PID>`로 확인. PID 42의 s6 래퍼는 root지만 실제 게이트웨이가 아님).
위 설치를 root로 했다면 컨테이너 안 root 셸에서:

```bash
cd /opt/data
chown -R hermes:hermes .local/share/python_keyring .config/python_keyring \
  .config/kiwoom .cache/kiwoom .local/share/uv/tools/kwcli
chown -h hermes:hermes .local/bin/kiwoomcli
su -s /bin/bash hermes -c 'HOME=/opt/data /opt/data/.local/bin/kiwoomcli auth status --profile 모의계좌' \
  | grep -E "모드|자격 증명 존재|토큰 유효|지금 API"
```

2026-09-28 결과: `demo` / `예` / `예` / `예`. 이후 작업은 `docker exec -it -u hermes "$HC" bash -l`로 들어가서 합니다
(root로 `kiwoomcli`를 쓰면 토큰 캐시가 root 소유로 다시 생길 수 있음).

## Sam 프로필에서 kiwoomcli 쓰게 하기 (이 VPS에서 필수)

Hermes는 에이전트 터미널에 **프로필 전용 HOME**을 줍니다(`terminal.home_mode: auto`).
Sam의 터미널은 `HOME=/opt/data/profiles/sam/home`, `HERMES_HOME=/opt/data/profiles/sam`이고, 로그인 셸이
PATH를 기본값으로 초기화한 뒤 **그 HOME의 `.profile`**만 `~/.local/bin`을 붙입니다. Sam HOME에는 `.profile`이 없어
`kiwoomcli: command not found`가 났습니다(2026-09-28). 또 HOME이 달라 키 파일(`~/.config/python_keyring` 등)도 못 찾습니다.

Sam 전용 HOME에만 실행 스크립트와 `.profile`을 둡니다. Ada·Noah·기본 프로필에는 키움 CLI가 생기지 않아
8.4의 직무 분리와도 맞습니다. 모두 `/opt/data` 볼륨 안이라 이미지 업데이트 후에도 남습니다.

```bash
# 컨테이너 안, hermes 사용자
SAMHOME=/opt/data/profiles/sam/home
mkdir -p $SAMHOME/.local/bin
cat > $SAMHOME/.local/bin/kiwoomcli <<'EOF'
#!/bin/sh
HOME=/opt/data exec /opt/data/.local/bin/kiwoomcli "$@"
EOF
chmod 700 $SAMHOME/.local/bin/kiwoomcli
[ -e $SAMHOME/.profile ] || cat > $SAMHOME/.profile <<'EOF'
if [ -d "$HOME/.local/bin" ]; then PATH="$HOME/.local/bin:$PATH"; fi
EOF
# 확인: Sam 환경 흉내
env -i HOME=$SAMHOME bash -lc 'command -v kiwoomcli; kiwoomcli auth status --profile 모의계좌 | grep -E "모드|지금 API"'
```

2026-09-28 결과: `/opt/data/profiles/sam/home/.local/bin/kiwoomcli`, `demo`, `예`.

주의: 메신저에서 "Sam"을 불렀는데 `HERMES_HOME=/opt/data`로 답하면 **기본 프로필 봇**이 받은 것입니다
(이 VPS의 텔레그램 봇은 default 프로필). 확인은 `hermes -p sam`으로 하거나 Sam 전용 채널에서 합니다.
기본 프로필에 키움 CLI를 넣어 "해결"하지 않습니다.

## 게이트웨이 경로로 한 번 더 확인 (중요)

## 주의

- `/opt/data` 전체를 묶는 백업(`hermes-complete.tar.gz` 등)에는 이제 이 키 파일도 들어갑니다.
  백업을 VPS 밖으로 옮기거나 공유하지 않습니다.
- 키를 바꾸거나 지울 때도 `kiwoomcli setup`/`kiwoomcli auth` 명령을 씁니다. 파일을 손으로 편집하지 않습니다.
